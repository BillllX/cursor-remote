# iOS 易用性与功能层级评估

评估日期：2026 年 11 月 16 日。覆盖小驳首页、助理中心、任务栏目、产物、设置、工作台与即时消息的入口，以及输入输出的文字展示。本次为代码与交互结构评估，尚未完成登录后的真机任务测试，以下优先级代表设计判断，不代表用户测试数据。

初次评估发现的主要问题是入口组织和阅读规则：小驳对话作为默认首页很明确，但工作台、消息与设置共用入口，助理中心内部又有两层栏目；正文排版已有复用基础，字号仍存在差异。建议保留对话优先的方向，先改善入口可发现性，再收敛内容和状态展示。

## 本次已完成

- 贴纸形象增加周期眨眼、思考时视线移动、接收输入时声波明暗变化、执行轨迹旋转、星芒呼吸和完成时一次跳跃与爱心放大。32pt 导航形象省略外围轨迹，112pt 形象呈现完整细节。
- 保留八态对应关系、完成后短暂反馈和静态离线表情。开启减少动态效果、应用进入后台或视图移除时停止连续更新；小尺寸更新上限为每秒 15 次，大尺寸为每秒 30 次，实际能耗仍需设备测量。
- 输入框、用户消息、助理正文和表格正文默认字号对齐到 17pt，继续使用各自已有的动态字号支持。标题、表头、代码和说明文字保留层级差异。
- 助理中心入口与栏目按钮的最小点击高度补齐至 44pt，入口同时保证 44pt 宽度。
- 产物页在助理数据未到时显示加载提示与重新加载入口；已取得状态但缺少产物能力时才显示不可用，避免把加载过程误判为版本不支持。
- 工作台空状态更明确地提示点按左上角查看对话。

## 功能层级

| 优先级 | 评估时的结构与影响 | 建议与验收方式 |
| --- | --- | --- |
| 高 | `PhoneSettingsScreen` 承担设置、工作台和消息切换，首页账户图标还承载其它空间的未读提示。用户需要知道账户入口内含功能空间。 | 将空间切换与设置分组，给工作台和消息提供可见文字入口。先验证新用户能否在不打开设置的情况下找到消息；若保留极简首页，可采用有文字的空间菜单。 |
| 中 | 助理中心第一层为待处理、任务与委派、产物、同事；任务下还有待办、委派、提醒计划。窄屏横向滚动时后面的栏目不一定可见。 | 保留中心归档职责，用“待处理”“任务”“产物”“同事”表达同一级对象。任务内再区分待办、委派、计划；大字号下允许换行或菜单承接，避免缩小字体。 |
| 中 | “同事”栏目进入“同事与通行证”，人员协作和接入凭证被放在同一页。 | 默认展示同事，把通行证与访问凭证收进该页的管理入口；普通用户先看到协作对象。 |

路由检查确认：`PhoneRouter.go` 会将任务与产物归入助理中心，并替换导航路径。栏目切换没有持续压栈的问题，这部分应保留。

## 易用性与反馈

行动区按屏幕高度和大字号限制确认卡、进行中任务的数量，符合让对话保持可见的目标。后续应在键盘展开、同时有待批与进行中任务时检查剩余阅读空间，尤其是小尺寸 iPhone。验收时应保证最近一条回复和输入操作仍可触达。

连接、同步、审批和失败都有文字入口，形象状态也消费现有客户端状态。这一做法应保留：动画帮助识别状态，失败原因和下一步操作仍由文字承担。当前形象的“接收输入”由草稿非空触发，不等同于麦克风正在录音，文案和声波不应被解释为实时录音状态。

产物页本次已区分首次加载与能力缺失。后续应把这一规则推广至其它列表：分别呈现首次加载、加载失败、内容为空、筛选无结果和版本不支持；失败提供重试，筛选无结果提供清除筛选，不能用同一个空状态代替。

## 输入输出展示一致性

助理正文、任务详情和部分产物/通知详情已经复用 `ProseLines`；用户输入保留纯文本，即时消息也采用纯文本气泡。这些语义差异可以保留，但字号、段落间距、附件打开方式和复制后的原文应统一。

本次先统一了正文默认字号。下一步建议从下列规则收敛：

1. 同一份助理结果在会话、任务详情、通知详情和产物预览中使用同一正文渲染入口；Markdown、表格、链接和代码块在这些位置应保留同样的内容与顺序。
2. 用户输入继续原样展示，防止 Markdown 解释改变用户发送的字符；复制和编辑均回到原文。即时消息已有复制等上下文操作，增加文字选择前要验证与气泡长按菜单、链接点击的冲突。
3. 正文左右对齐方式、正文宽度和附件卡片可以随容器调整，但文件标题、类型、大小、打开与下载动作应一致。先检查图片加文字、长文件名和多个附件组合。
4. 表格表头与代码使用较小字号是有意的层级差异；大字号下应继续检查横向滚动、换行和复制，避免为了统一字号损害可读性。

## 当前导航方案

按产品使用频率调整为小驳优先：iPhone 移除顶部常驻空间栏，左上角仅保留侧边栏入口。侧边栏按当前对话、记忆与能力分组；模型、执行策略、写入前确认、撤销和检查点归入当前对话。任务与产物统一从右上角助理中心进入，侧边栏不再重复提供入口，也移除了回到对话按钮。记忆与规则、技能工厂、同事、设备权限放入能力分组。设置与工作台固定在侧边栏底部，不随列表滚动。照片、文件、语音仍就近放在输入框旁。工作台继续使用原有返回小驳的入口。

iPad 移除底部多空间切换栏，工作台入口固定在小驳侧栏底部，设置收进侧栏底部；进入工作台后保留返回小驳的按钮。iPhone 与 iPad 均隐藏消息入口，阻止消息空间切换和消息推送跳转；iPad 原先保存的消息空间在启动时回到小驳。消息底层协议和数据模型暂时保留。

助理中心栏目简化为待处理、任务、产物、同事。栏目完整显示所需宽度超过可用宽度时改用菜单，不再依靠横向滚动寻找后面的入口。同事页默认展示已有通行证记录和待批提案；门户及新增凭证表单通过“访问管理”显示。已有同事记录中的权限编辑与吊销入口继续保留。

会话、iPhone 任务及委派详情、通知详情、iPad 简报及任务详情统一使用同一个分段正文渲染器，代码围栏、表格、链接和空段落复用相同规则。产物来源摘录保留短摘要，展开后使用同一正文渲染器并支持文本选择。用户发送内容及普通即时消息仍保留原文。

文件在会话、委派和 iPad 详情中继续使用已有的 TurnFileCards。产物行新增同一套文件类型与大小说明，预览、分享继续调用既有文件处理入口。任务首次加载时增加提示与重试；产物列表区分全部为空和筛选无结果，后者提供清除筛选。

模型入口增加 CPU 图标，侧边栏与输入框旁共用可搜索的卡片网格选择面板。面板支持按厂商筛选，以名称、模型 ID 或厂商检索，展示当前模型，并在辅助功能大字号模式下改为单列。

## 验证与后续验收

第二轮修改通过 iOS 模拟器目标 Debug 编译和 Swift 语法检查。两项旧静态契约脚本仍失败：导航脚本要求 Web 与 iOS 的图标枚举完全相同，但 iOS 尚缺 kb、schedules、settings、skills；头像脚本仍要求状态点读取 store.activeId，而当前已提交代码使用 assistantTargetChatId。两处差异均已存在于本轮修改前。

后续设备验收应覆盖：首次找到工作台、从未读消息进入并返回小驳、提交带图问题、批准任务并找到产物、断线后重试、对比同一内容在会话和任务详情中的显示。另需检查键盘展开且同时存在待批与进行中任务时的阅读空间；大字号下侧边栏固定工作台按钮是否可触达，助理中心是否正确切换为菜单。动画检查浅深色、减少动态效果、后台恢复和快速状态切换。当前尚未完成登录后的真机交互与能耗测试。
